# 默认与示例配置保留弱口令

## 问题现象

公共配置为数据库和 Redis 提供了 `password`、`123456` 弱口令默认值，本地示例配置也保留了 Redis 演示口令。开发者在未显式配置环境变量时，容易直接沿用这些默认凭据。

## 排查过程

1. 检查 `application.yaml`，确认 `DB_PASSWORD` 和 `REDIS_PASSWORD` 均带有弱口令回退值。
2. 检查 `application-local.example.yaml`，确认 Redis 密码仍为演示值 `123456`。
3. 检查启动文档，确认项目支持复制本地模板或通过环境变量提供真实凭据。
4. 扩展配置安全测试，同时约束公共配置和本地示例配置。

## 根因

本地开发便利性被写入了版本库公共配置，配置模板脱敏也不完整，导致弱口令从“个人环境选择”变成了“项目默认行为”。

## 解决方案

1. 将公共配置中的数据库、Redis 密码默认值调整为空，要求通过环境变量或本地忽略文件提供真实凭据。
2. 将本地示例中的 Redis 密码替换为 `your-redis-password` 占位值。
3. 在本地示例中补充管理员白名单和外置上传目录配置，避免启用安全修复后缺少部署说明。
4. 扩展 `ConfigurationTemplateSanitizationTest`，防止弱口令默认值回归。

## 验证结果

- `mvn -q -Dtest=ConfigurationTemplateSanitizationTest test`：通过，共 2 个配置与部署检查。
- `mvn -q -DskipTests test`：通过，配置变更未破坏主代码或测试代码编译。

## 关键收获

配置文件同样属于安全边界：公共配置应默认安全，本地便利凭据应留在 Git 忽略文件或环境变量中，并通过自动化测试阻止弱口令回归。
