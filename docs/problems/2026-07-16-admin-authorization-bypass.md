# 后台接口鉴权绕过

## 问题现象

登录拦截器将 `/admin/**` 和 `/upload/**` 配置为匿名路径，导致商家入驻审核接口和上传接口无需登录即可访问；失败任务查询、重试和忽略接口虽然要求登录，但任意普通用户登录后都能执行运维操作。

## 排查过程

1. 检查 `MvcConfig#addInterceptors`，确认 `/admin/**`、`/upload/**` 位于登录拦截器排除列表。
2. 检查 `AdminShopApplyController`，确认列表、详情和审核接口均位于 `/admin/shop/apply/**`。
3. 检查 `VoucherOrderFailTaskController`，确认其中包含失败任务重试和人工忽略等高权限操作。
4. 检查 `User`、`UserDTO` 和数据库脚本，项目当前没有可复用的角色字段或 RBAC 模型。
5. 采用配置化管理员用户 ID 白名单作为最小可落地方案，并保持空配置时默认拒绝访问。

## 根因

项目仅实现了“是否登录”的粗粒度校验，没有管理员角色模型；同时为调试方便将整个后台和上传路径加入匿名白名单，形成了认证绕过和水平权限扩大问题。

## 解决方案

1. 从登录拦截器匿名列表移除 `/admin/**` 和 `/upload/**`。
2. 新增 `AdminInterceptor`，区分未登录的 401 和无管理员权限的 403。
3. 对 `/admin/**`、`/voucher-order-fail-task/**` 注册管理员拦截器。
4. 新增 `app.security.admin-user-ids` 配置，通过环境变量 `ADMIN_USER_IDS` 注入逗号分隔的管理员用户 ID。
5. 管理员配置为空时使用空白名单，确保后台接口默认拒绝而不是默认放行。
6. 新增单元测试覆盖未登录、普通用户、管理员、空配置和非法配置场景。

## 验证结果

- `mvn -q -Dtest=AdminInterceptorTest test`：通过，共覆盖 5 个权限场景。
- `mvn -q -DskipTests compile`：通过。

## 后续演进

当前白名单方案用于在没有角色字段的现状下快速封堵高风险接口。后续应在用户模型中增加角色/权限表，并迁移到统一 RBAC 或 Spring Security 方法级授权。

## 关键收获

在缺少完整 RBAC 的遗留项目中，可以先用“登录校验 + 配置化管理员白名单 + 默认拒绝”快速建立最小权限边界，再逐步演进到数据驱动的角色权限模型。
