# 前端依赖分包优化测试报告

## 1. 测试结论

本轮分包配置通过生产构建验证。业务入口从约 1,095.46 kB 降为 8.37 kB，框架、Axios、Element Plus 和其他依赖形成独立缓存分块。由于 Element Plus 仍为全量引入，首次加载总资源量没有同等幅度下降，803.67 kB 的大分块告警仍然存在。

## 2. 执行结果

| 检查项 | 结果 | 说明 |
|---|---|---|
| `npm run build` | 通过 | Vite 4.5.14，1,678 个模块转换成功 |
| 业务入口 | 通过 | 8.37 kB，gzip 3.36 kB |
| `http-vendor` | 通过 | 45.44 kB，gzip 17.68 kB |
| `vendor` | 通过 | 115.91 kB，gzip 41.26 kB |
| `vue-vendor` | 通过 | 123.53 kB，gzip 47.92 kB |
| `element-plus` | 部分通过 | 已独立分块，但仍为 803.67 kB，gzip 254.24 kB |
| Element Plus CSS | 记录风险 | 357.51 kB，gzip 47.83 kB |
| `npm audit --audit-level=moderate` | 未通过 | 2 个漏洞：1 moderate、1 high |

## 3. 优化前后对比

| 指标 | 优化前 | 优化后 | 结论 |
|---|---:|---:|---|
| 主入口 JavaScript | 1,095.46 kB | 8.37 kB | 业务入口与依赖完成解耦 |
| 主入口 gzip | 364.45 kB | 3.36 kB | 入口缓存失效成本降低 |
| 独立第三方分块 | 未明确拆分 | 4 类依赖分块 | 长期缓存边界更清晰 |
| 最大 JavaScript 分块 | 约 1,095.46 kB | 803.67 kB | 仍需治理 Element Plus 全量引入 |

> 上述对比说明的是产物组织变化。各依赖仍可能参与首次加载，因此不能把入口缩小比例等同于首屏下载体积缩小比例。

## 4. 依赖审计结果

审计问题来自 Vite 间接依赖的 esbuild。npm 提供的自动修复方案会安装 Vite 8.1.5，而项目当前实际构建版本为 Vite 4.5.14，跨越多个大版本。为避免在没有 Node 版本、插件兼容和页面回归验证的情况下引入破坏性变更，本轮未执行 `npm audit fix --force`。

## 5. 剩余风险

1. Element Plus 采用全局完整引入，JavaScript 和 CSS 体积仍大。
2. 尚未执行浏览器端首屏耗时、缓存命中和 UI 功能回归测试。
3. Vite/esbuild 安全公告尚未消除，需要独立升级任务和完整兼容性验证。
4. 当前工作区还包含其他未提交的前端功能改动，本次构建验证覆盖了其编译结果，但本轮提交不会包含这些文件。

## 6. 最终结论

本轮达成低风险的依赖缓存分层目标，可以提交 `vite.config.js` 配置。下一阶段若要降低真实首次加载体积，应单独实施 Element Plus 按需引入，并配套页面回归和构建体积对比。
