# ES 搜索缓存与降级 Spec

- 日期：2026-10-01
- 状态：待评审
- 来源：`docs/reports/2026-10-01-loadtest-baseline-report.md` P1 问题
- 关联 Plan：`docs/feature-workspace/plan/2026-10-01-es-search-cache-plan.md`

## 1. 背景

商户搜索直连 ES，压测 p95 221ms（avg 81.5ms），且 ES 故障时整个搜索功能直接不可用（报"服务异常"）。

## 2. 需求

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| R1 | 搜索结果 Redis 缓存，TTL 30s；缓存键含 keyword/page/size/坐标 | 相同请求 30s 内第二次命中缓存，p95 降至 30ms 以内 |
| R2 | ES 异常时降级为 DB 模糊查询（LIKE），功能可用 | 停掉 ES 容器后搜索仍返回结果（DB 数据） |
| R3 | 商户数据同步 ES 后，搜索缓存失效 | sync 后新数据立即可搜到 |
| R4 | 缓存不破坏距离排序语义 | 带坐标的请求坐标参与缓存键 |

## 3. 非目标

- 搜索词联想/热搜统计
- 缓存穿透布隆过滤器（搜索场景关键词发散，短 TTL 即可）
